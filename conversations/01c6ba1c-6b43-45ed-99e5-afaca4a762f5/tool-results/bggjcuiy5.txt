### G20

**Status:** ACCEPTED · **Verified:** yes

**Resolution:** W0: open; `impute_with_selector` at `feature_extraction.py:2468` → W5.

**Where:** `src/core/feature_extraction.py (impute_with_selector, fit_selector, RobustFeatureSelector._clean_features), src/core/feature_selection_poolsel.py (clean_matrix, clean_feature_frame), src/core/stages/features.py:747-827, src/core/stages/holdout.py:1025-1058`

Review `impute_with_selector` and its effect on feature selection. It does not change which features are chosen. `select_features` (holdout: `_select_holdout_features`) finishes first; `fit_selector(..., feature_names=selected)` only stores medians; `impute_with_selector` then `fillna`s the train, test, and estimation frames. The effect is that selection scores one fill and the model trains on another. Ensemble and the other rankers run `_clean_features` on a copy: median when a column is under 10% missing, 0 otherwise. `patient_mrmr_consensus` skips that call, but poolsel's `clean_matrix` fills every NaN with 0 before scoring, and `clean_feature_frame` uses the same 10% rule before the redundancy step. That copy is thrown away. The medians written onto `FeatureSelectorState` are the raw training-column medians (NaNs skipped), and `impute_with_selector` applies that median to every selected column, including columns selection filled with 0. A feature can win the funnel on zero-filled values and then be fit on median-filled values. The medians are taken on the whole train+validation pool, so the later validation split is filled with constants that validation rows helped set. The blind test and the estimation set do not contribute, which is correct. A selected column that is entirely NaN stores `nan`, and `fillna` leaves it missing, so Easy Ensemble still sees the NaN it was meant to remove. Make the matrix that is scored and the matrix that is trained the same fill, or record the difference as intentional.
